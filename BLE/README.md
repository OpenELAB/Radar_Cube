# Radar_Cube
Wireless reversing radar module
- Cude - In-car control module
- Sensor - rear radar sensor module

## Scheme comparison
- The main control esp32c3 comes with WiFi and Bluetooth wireless communication modules. At the initial stage, the solution of external nrf module will not be considered.
- Power consumption comparison: Both wifi and esp now are based on wifi communication, and the power consumption is relatively high. Because Bluetooth has a ble version, the power consumption will be significantly lower than the wifi-based solution. Therefore, as the initial line of sight solution, ble was chosen as the communication solution.

## Current solution:
- Master: esp32c3
- Communication: Onboard BLE module
- Low power consumption idea: In the light sleep mode, the Sensor module performs periodic ble signal scanning, wakes up when it monitors the signal from the Cube, and then starts collecting radar data and transmits it to the Cube.

## Follow-up planning
1. Sensor radar data collection and processing
2. The communication content design of two devices may require encryption or other methods to ensure that multiple sets of devices do not conflict.
3. Low power consumption design, first look at the power consumption after adding light sleep mode, and then see if further optimization is needed
    - Using scan_interval/window duty-cycle, C3 can implement "low-power monitoring" under light sleep, and the CPU will not be truly woken up until the broadcast is scanned.
    - If the trigger end broadcasts continuously for 1–2 s, the probability of missed connection is almost negligible (alignment problem is eliminated through non-integer period + jitter mechanism).
